2026-09-19 - Blockquote marks in RenderPureMarkdown (7fe3870)
-------------------------------------------------------------
Quoted text in the Text/MD reading views now keeps its mail syntax: every line inside a blockquote
starts with a de-emphasized "> " (one per nesting level, so "> > " for a quote in a quote), like the
quoted lines of a reply in the source, instead of showing only the shaded quote box. The marks are
added at the start of each quoted paragraph, after each line break inside it, before a heading, and
on every line of a fenced code block inside a quote. Text outside the quote is untouched, and the
quote depth is reset for every render. Tests added for plain, nested and mixed quotes.


2026-09-19 - Collapsed accounts and running syncs on load (3a3a00e)
------------------------------------------------------------------
- After the page loads, every account in the sidebar is collapsed: with the combined Inbox showing,
  no account is selected yet. A side effect is that a collapsed account's folders are not fetched
  from IMAP at all until you expand it (or select something in it). Expanding by click works as
  before; an account also expands when something in it gets selected.
- Sync jobs that were already running when the page loaded (an earlier visit, another tab, or the
  automatic sync of another browser) are picked up: on load each account's job history is checked
  once, and a pending/running job gets its spinner and "Syncing n/m..." tooltip and is followed to
  its end, after which the app refreshes like after any sync (folder counts, open list, combined
  lists, unread badge, new-mail announcement). A "Sync now" click meanwhile does nothing new, since
  that account already counts as syncing. Jobs orphaned by a server restart were already marked
  failed at startup, so only really running ones show.
- Tests: initial collapse and expand; resuming a running job (spinner and progress), following it to
  its end, and no spinner for a finished or absent one. The shared test helper now expands the
  account before going into its Inbox.


2026-09-19 - Better recipient autocomplete (8c6966f)
---------------------------------------------------
1. Punctuation no longer matters. A contact stored as 'First Lastname' <flastname@example.com> wasn't
   found by typing First because the quotes were part of the first word. Names are now compared as
   plain words (case and any punctuation ignored, letters/digits of any script, so umlauts work):
   First, 'First, last first and first-last all find it. Every typed word has to be the start of some
   word in the name (irst finds nothing), or the address has to start with what you typed (that part
   keeps its punctuation: first.l). Quotes around names are also stripped when a contact is stored,
   and existing contacts are tidied once at startup (so old data is fixed too, and the suggestion
   shows First Lastname without quotes).
2. Contacts from other accounts: instead of a button, they are appended automatically, under a
   "From your other accounts" heading, after the current account's own matches (up to 5, ranked the
   same way; an address known to several accounts shows once with its counts added up; never an
   address the current account already has). This account's people always stay first, so the
   "only this account" feel is kept, but you never have to click anything to reach the rest, and the
   arrow keys walk through both groups. I chose this over a button because a button hides the
   contacts exactly when you need them, at the cost of a slightly longer list. The API only does it
   with scope=all (the recipient fields always ask for it); otherwise it is still this account only.
- Tests: quoted/punctuated/umlaut names, word order, address prefixes, the startup repair; other-account
  ranking, caps, dedupe and isolation between users; the heading and keyboard/mouse selection in the UI.


2026-09-19 - Bulk selection in the combined lists (72325f4)
-----------------------------------------------------------
Cause of "Shift-select doesn't work anymore": since the app opens on the combined Inbox, you were in a
results list, and only a single account's folder list had multi-select (the account's own Inbox in the
sidebar still did). Now the combined Inbox/Sent and search results have it too:

- The bulk bar (mark read/unread, Move, Delete) works on such a selection, which can span accounts: it

  only go to Trash. Move is only offered when everything selected is from one account (folders differ
  per account); the sidebar switches to that account so its folders are what Move lists. Rows that were
  moved leave a combined Inbox/Sent, and are updated in place in a search.
- Counts: the selected account's folder badges and the combined Inbox badge update; other accounts'
  folder badges in the sidebar are only refreshed by their next sync/reload.
- A new search or another mailbox starts with a clean selection. Folder-list behavior is unchanged.
- Tests: selecting (click, range, toggle), Cmd/Ctrl+A and Shift+arrows, per-account bulk requests for
  mark read / delete / move, Move visibility, selection reset; the existing bulk tests still pass.


2026-09-19 - Empty password allowed (55118e8)
----------------------------------------------
Changing the password in Settings > Credentials now also accepts an empty new password (leave both
new-password fields empty): the profile becomes passwordless, like the built-in default profile. The
server already allowed this; only the form blocked it. It is the same all-or-nothing change as any
other: the saved account passwords are re-encrypted with the key an empty-password login derives (so
they stay readable), and the other sessions are signed out. The toast says "Password removed." and the
form notes that anyone who can reach the app can then sign in to the profile. Tests: model (empty new
password keeps accounts readable) and the form (an empty new password is sent; a mismatched
confirmation is still caught).


2026-09-19 - Change password, tabbed Settings (a3f2792)
-----------------------------------------------------
- The Settings dialog now has three tabs: Inboxes (sync interval, folders in the combined Inbox),
  Notifications (browser notification, toast, sound) and Credentials (change password). Inboxes and
  Notifications share one Save button (edits on both tabs are saved together); Credentials has its
  own "Change password" button.
- Changing the password needs the current one, a new one and its confirmation (the passwordless
  default profile leaves "current" empty and can thereby set a first password).
- The important part - the encryption: the saved IMAP/SMTP passwords of your mail accounts are
  encrypted with a key derived from your login password and a salt. So a password change decrypts
  every account secret with the old key and re-encrypts it with the key for the new password and a
  fresh salt, in the same transaction as the new password hash: it is all-or-nothing. If some
  account's secrets can't be decrypted it refuses with a message naming that account (re-enter its
  passwords in Account settings first) and changes nothing.
- Sessions: the key lives in server memory per session. The session you change the password in is
  given the new key and keeps working; your other sessions/browsers are signed out (their keys would
  be stale), and the toast says how many.
- New endpoint POST /api/auth/change-password. The existing PATCH /api/users/:id (password) only
  swapped the hash and would have left every saved account password undecryptable; it now needs
  currentPassword as well and goes through the same re-encryption.
- Tests: model (re-encryption, wrong password, all-or-nothing, default user), integration (full HTTP
  flow incl. other session signed out and secrets readable with the new key/salt), and the tabs and
  form in the frontend. The old model test for updateUserPassword was replaced.

2026-09-19 - New-mail notifications (08250c8)
----------------------------------------------
- Two opt-in settings in the Settings dialog ("New mail notifications"), stored on the server:
  * Browser notification: a desktop notification with only the sender and subject (no content) for
    one new mail, or a count like "20 new mails" (with the senders) when several arrive. Clicking
    it focuses the tab and opens that message, or the combined Inbox. Turning it on asks the
    browser for permission; if refused, the option isn't saved and the dialog explains why.
  * Toast in the app: sender as title, then subject, the first ~200 characters of the text, date,
    To and Cc, with an "Open" button (or "20 new mails" with "Show inbox"), plus a sound. Sounds:
    crystal_clear (the default), cute_bell, marimba or none, with a play button to try them. The
    files live in src/sounds/ and are bundled with the app. The sound belongs to the toast only.
  If both are on, both fire.
- How new mail is detected: after every sync (manual or interval) the client calls the new
  GET /api/unified/inbox/new?afterId=..., which returns unread, non-draft mail in the combined
  Inbox's folders (respecting the folder option) that is newer than the last id seen and less than
  a day old. Mail read on another device and the backlog of a first sync therefore don't notify.
  The starting point is read when the app loads, so mail that arrived while it was closed isn't
  announced; it moves forward on every sync even when notifications are off.
- Notifications only appear after a sync finishes, so with no sync interval set you only get them
  after clicking "Sync now".
- Also: the star toggle in result lists (previous entry) was committed separately.
- Tests: backend (new-mail query, settings validation) and frontend (toast content, sounds,
  browser notification and click targets, bundles, permission flow); the test setup got a small
  plugin so bun test can import the .mp3 files.

2026-09-19 - Settings dialog, read-only delete tombstones (e0b1ae1)
--------------------------------------------------------------------
- Folder mail in the combined Inbox: now an opt-in user setting, off by default. When on, the
  combined Inbox and its unread badge also cover each account's other incoming folders. Sent,
  Drafts, Trash, Junk and Archive are left out, recognised by the server's folder flags (learned
  from its folder list) or by common names like Papierkorb and Spam. Each row still shows which
  folder the message is in.
- Deleting in read-only mode: a small tombstone table (deleted_uids) instead of an
  is_permanently_deleted flag. Only the message's UID is remembered; the message itself (body,
  attachments) is really deleted. A flag would have needed a filter in every list, search, count
  and contact query. The next sync skips tombstoned UIDs and counts them in its "newer than"
  cutoff (deleting the newest message used to make it look new again), and drops a tombstone once
  the server no longer has that message.
- Local-only moves in read-only accounts tombstone the old folder's UID too, and the moved row
  loses its old UID (it belonged to the old folder and could collide with a real message in the
  destination). This changes the old behaviour of keeping the UID; the integration test was
  updated.
- Settings dialog: the username next to logout is now a subtle button with a gear icon ("Settings"
  for the default profile). Two fields, stored on the server: sync interval in minutes (whole
  number 1-1440, empty = never, the default) and the combined-Inbox folder option. While the web
  client is open it syncs on that interval; an account still busy with the previous run is
  skipped and failures to start an automatic sync stay quiet. Sync state moved out of the sidebar
  rows into one shared hook (useSyncJobs) so manual and automatic runs can't overlap. The interval
  only fires while the tab is open; the first run happens after one full interval.
- Removed the never-used downloadIntervalSeconds from settings.json (an existing file that still
  has it is unaffected).
- Tests added for the tombstones, folder inclusion rules, the new settings and the dialog.

2026-09-19 - Sync all folders, unread badge, paperclip, calmer tree refresh (1b57ade)
--------------------------------------------------------------------------------------
- Unread badge on the combined Inbox: counts unread messages across all accounts' Inboxes via
  GET /api/unified/inbox/unread. Drops immediately as messages are read; re-read from the server
  after a sync or send. A partial index covering only unread rows keeps the count cheap.
- Tree reloading during sync: after a sync finished, the folder list was reloaded behind a
  "Loading folders..." spinner, blanking the tree. Now only the very first load for an account
  shows the spinner; later refreshes update counts in place. Switching accounts no longer briefly
  shows the previous account's folders. When a sync ends, folder counts, the open list, the
  combined lists and the unread badge are refreshed.
- Empty folders: "Sync now" only ever synced the Inbox. It now syncs every folder, Inbox first,
  with cumulative progress. It skips unselectable folders and Gmail-style "All Mail"/"Flagged"
  views. If one folder fails the rest still sync and the job ends failed naming the folder and
  error. The CLI's --folder and the API's folder field still limit it to one folder. The server
  also remembers each account's Sent folder while syncing.
- Paperclip on rows with real attachments (inline images don't count), in folder lists, search
  results and the combined lists. List rows now carry an attachment count.
- Existing accounts need one full "Sync now" to pull their other folders; each folder is fetched
  in one go with no batching yet.

2026-09-18 - Recipient autocomplete, faster list, infinite scroll (421682c)
---------------------------------------------------------------------------
- Recipient autocomplete: GET /api/accounts/:email/contacts?q=... suggests addresses by prefix
  or name word. Ranking: people who wrote to you, then people Cc'd, then everyone else (mainly
  people you only sent to); within each group by frequency, then recency. A contacts table is
  updated whenever a message is stored or a draft is sent; existing databases are backfilled once.
  To, Cc and a new Bcc field use RecipientInput with keyboard and mouse selection, debounced and
  cached lookups. About 3 ms on 20,000 contacts.
- Slow message list: the query loaded every column including full HTML bodies and raw headers,
  and sorted the whole folder each time. It now loads only what the list shows (snippet cut to
  200 characters) and uses an index on account, folder, date and id. On 5,000 messages: about
  296 ms down to about 1 ms. List rows no longer carry the HTML body or raw headers; opening a
  message still fetches it in full.
- Infinite scroll: the list loads 100 messages at a time and fetches the next page near the
  bottom. Refreshing keeps already scrolled-in pages; duplicates from shifting pages are dropped.
- Known gap noted at the time: the paperclip icon never showed because list rows had no
  attachment info (fixed in 1b57ade).


2026-09-18 - Fix "Too long argument" on resumed sync (8356a44)
---------------------------------------------------------------
- The flag reconcile sent every stored UID; it now sends one min:max range (for example
  1:48213). UIDs stored locally but missing from the response are still treated as deleted.

2026-09-18 - Download progress on the sync job (44fcb9e)
---------------------------------------------------------
- GET /api/accounts/:email/downloads/:id shows the download count while messages are still being
  downloaded: progressCurrent updates per downloaded message (same count as the server log's

2026-09-18 - Sync logging (82a86c4, 28aed1d)
---------------------------------------------
- The server console prints each sync step: [sync <timestamp>] lines for connection target
  (never the password), reconcile/fetch stages, message counts, progress every 25 messages,
  total time. Silent under bun test.
